# Notion 排版 MVP

输入：一篇已经成立的 Markdown 文章（标题、段落、列表、引用等）。
输出：Notion-flavored Markdown，可直接交给 Notion MCP 的 `create-pages` / `update-page`。

完成标准：输出与原文信息一致；标题层级不跳级；每一个特殊块都有明确的排版理由；整页读起来是一篇布局过的文章，而不是语法练习。

## 职责边界

只做排版：整理骨架、选择块级结构和阅读节奏。不判断文章主题是否成立，不改写文字，不补缺的内容，不替作者整理没有说清的逻辑。

如果输入是想法、草稿或对话记录，先说明这里只负责排版，请先把文章整理成文本；不要假装读懂了就开始加工。

## 排版判断（先于语法）

### 骨架

先通读原文，找到文章真正的脊柱：主题、开头给了读者什么承诺、各节在推动什么、结尾落在哪里。再按这个路径安排标题层级：

- H1 是页面标题；H2 是主章节；只有章节内部确实需要进一步分组才用 H3，不跳级。
- 章节标题表达“这一部分让读者得到什么”，不写成关键词罗列；没有实际作用就不加标题。
- 各节顺序保留原文逻辑。只有明显错位、且调整只改变顺序不改变内容时（例如把背景放到结尾）才调整，并说明。
- 开头保持正文段落，不把承诺转换成 Callout；结尾不追加总结，让原文的自然结尾保留下来。

### 块选择

每个块什么时候用、怎么选，以 [references/notion-syntax.md](references/notion-syntax.md) 的「块选择」表为准；数据块见 [references/notion-data.md](references/notion-data.md)。总原则：只保留支撑阅读路径的强调，不为“看起来丰富”堆块。

### 节奏

阅读节奏由内容决定，不是把所有段落都切成短段：

- 段落长度跟随思想：短段承担强调或转折，长段推进论述，两者混用。
- 一个语义观点通常由 1–2 段完成；观点之间用 `<empty-block/>`，同一观点内的段落不插空行。
- 列表和表格视作一个整体模块，内部不拆散；标题后加 `<empty-block/>` 让标题与正文分离。
- 转场任务交给章节标题，不添加“接下来我们看看”这类填充句。
- 结尾在最后一句自然停止；如果原文留有空白感，不要用总结填满。

## Notion 语法与输出

写入前先判断这次内容需要的平台能力，再读取对应 Reference：

- 页面内容用 Markdown 排版：完整阅读 [references/notion-syntax.md](references/notion-syntax.md)，按其中已验证的语法生成。
- 需要数据库、图表或数据视图：完整阅读 [references/notion-data.md](references/notion-data.md)，这部分不能只靠 Markdown，需要配合 Notion 工具。

完整语法来自 MCP 资源，不在这里复述：

- 页面块语法：读取 notion://docs/enhanced-markdown-spec。
- 视图配置：读取 notion://docs/view-dsl-spec。

容易出错且必须遵守的硬规则：

- 子块缩进用 Tab，不是空格。
- 空行必须用独占一行的 `<empty-block/>`，不要用裸空行。
- 表格根据需要设置 `fit-page-width`；列宽可显式设置，也可留空自动分配，不强制 720px。
- Notion 内部页面用 mention；外部链接用普通 `[text](url)`。书签卡片 MCP 无法创建，不要写 `<bookmark>`（会被降级成 unknown）。
- Notion 不支持 H5/H6，统一折叠为 H4。

输出正文从第一级标题开始；如果调用方把 `title` 作为独立参数传入，正文从 H2 开始，避免重复页面标题。

## 交付

直接输出或写入 Notion-flavored Markdown。不添加“本文已优化”之类的说明 Callout，不解释 XML 语法，不加固定结尾。简短说明所做的排版决策；未改动的部分不逐条交代。

发现原文在内容层面的问题（缺证据、前后矛盾、章节错位会影响理解）时，明确指出，但不替作者改写或补充。
